fn 0x1030e enter_title
cmt 0x1030e Enter the title screen: title_just_entered = 0xff, set_palette_black, and if level0_assets_loaded is still clear, set it and load_level_assets(0) first. Falls into title_attract_loop either way.
fn 0x10332 load_level_assets
cmt 0x10332 Load the five files a stage needs, for level d0 (0..4). First it PATCHES THE FILENAMES: five bytes from level_bank_digits + 5*d0 are written into byte 6 of each of the four "A\HSC_n.DAT" names (0x16354/0x16368/0x1637c/0x16390) and into byte 7 of "A\LEVEL1.MAP" (0x1633f), so one record set serves every stage. Then a per-level sequence of load_file calls interleaved with disc-swap prompts (all of which are patched out in this build -- see the PATCH section). Bank digits per level: 0->HSC 0,1,2,3 + LEVEL1; 1->4,5,6,7 + LEVEL2; 2->8,9,A,B + LEVEL3; 3->0,1,3,B + LEVEL4; 4->8,C,3,7 + LEVEL5. | d0.w = level number. Copies the five ASCII digits from level_asset_digit_table into the HSC and LEVEL filenames in asset_file_table, then loads bank 0, the map and banks 1..3, inserting the "insert disc B" prompt on the levels whose banks are not on disc A.
proto 0x10332 level@D0
fn 0x104f2 title_attract_loop
cmt 0x104f2 The title/attract screen. Blacks the palette, scroll_y = 0, scroll_phase = 0x1e, rebuilds map_ptr/map_ptr_start from the map header, prescrolls prescroll_count+1 frames, then loops: sound_cmd(4) and wait for the sound module's byte at +30 to go non-zero. Exits with `rts` when joystick-1 FIRE is pressed and new_hiscore_pending is clear (the caller then starts a game); branches to hiscore_show_entry_screen when new_hiscore_pending is set. Joystick-1 LEFT copies title_word_easy into title_mode_word and sets hard_mode = 0, RIGHT copies title_word_hard and sets hard_mode = 1; both trigger the sound at 0x121e6. The attract text cycles on attract_page_timer, which reloads from attract_page_reload: below 0xc8 -> text_hall_of_fame, below 0x226 -> text_credits, otherwise text_publisher.
fn 0x10594 title_frame_step
cmt 0x10594 One attract frame: scroll_step(), then loop back into title_attract_loop's poll while scroll_y < 0xbb8 (3000); at 3000 the whole attract restarts. Reached only by branches from inside title_attract_loop -- it is not a separate callee.
fn 0x10698 build_text_display_list
cmt 0x10698 Interpret a text script into the 6-byte-per-slot display list at a1. The script is [start_x.b][start_y.b] then a byte stream: 0x00 = advance x by 8 (a space), 0x04 = advance x by 0x40, 0x05 = newline (y += 8, x = 0), 0x06 = x += the word at ADDRESS 0x40 (low memory, _etv_timer's high word -- almost certainly a bug), 0x09 = end, anything else = emit {x.w, y.w, code.b, enable=1} and advance x by 8. Character codes: 0xab..0xc4 = 'A'..'Z', 0xc5..0xce = '0'..'9', 0xcf = space, 0xd0+ = HUD glyphs.
proto 0x10698 script@A0 dest@A1
fn 0x106f2 hiscore_show_entry_screen
cmt 0x106f2 Build the hall-of-fame page: hiscore_reset_last_digit, render text_hall_of_fame into the display list, and if name_entry_done is clear also render text_enter_your_name. Falls through into hiscore_name_entry.
fn 0x10724 game_over_hiscore_check
cmt 0x10724 Game over. hard_mode = 0, hiscore_rank = 5; convert score_bcd to characters and compare against hiscore_table entry 5 (the 6th, lowest). If the score does not beat it, clear new_hiscore_pending and jump to 0x15754 (restart at init_new_game). Otherwise walk UP the table to find the rank, shift the beaten entries down one slot each with hiscore_shift_entry_down, copy the six score characters into entry+16, set new_hiscore_pending = 0xff and name_entry_timeout = 0, and jump to 0x15754. Entered by `adda.l #$40,a7 / bra` from read_player_input (the F10 abort) and from 0x13c90 (lives exhausted) -- both unwind rather than return.
fn 0x108aa hiscore_shift_entry_down
cmt 0x108aa Copy 13 bytes from entry+9 to entry+9+22, i.e. push this hall-of-fame row's name and score down into the next row while leaving the leading layout bytes and the rank digit at +8 where they are.
proto 0x108aa entry@A0
fn 0x108c0 hiscore_reset_last_digit  # ctx

fn 0x108f8 digits6_compare
cmt 0x108f8 Compare six character digits at a6 against the six at a5+16 (a5 is a hall-of-fame entry, so +16 is its score field). Returns d0 = -1 if a6 is lower or equal all the way, +1 if a6 is higher at the first differing digit. Both a5 and a6 are advanced past the compared bytes.

fn 0x10916 hiscore_name_entry
cmt 0x10916 Three-character name entry into hiscore_table + 22*hiscore_rank + 11. On first entry (name_entry_done clear) the three characters are filled with 0xcf (space). Joystick-1 right increments the character (wrapping 0xcf->0xab), left decrements (wrapping 0xab->0xcf), fire advances name_entry_cursor. On the third fire it calls check_cheat_name and sets name_entry_done; after that name_entry_timeout counts down and, at -1, resets everything (new_hiscore_pending=0, name_entry_cursor=0, name_entry_done=0, name_entry_timeout=0x32) and the attract loop resumes.

fn 0x10bec score_add_bcd
cmt 0x10bec Add a 3-byte BCD value to score_bcd: `lea $15a2d,a0` then three `abcd -(a1),-(a0)`, so the addends are the three bytes BELOW a1 and the accumulator is 0x15a2a..0x15a2c. a1 therefore points ONE PAST the value; the nine wrappers below pass score_award_values + 3, +6, ... +27, selecting 50/100/200/250/500/1000/3000/5000/10000 in order.

fn 0x10bfa load_file
cmt 0x10bfa Load one file. a0 -> an 8-byte record [dest.l][length.l] followed by the NUL-terminated DOS path; both longwords are RELOCATED in the image, so at run time the first is an absolute address. Copies them to load_dest / load_len, GEMDOS Fopen(name, mode 2) -> load_file_handle, Fread(handle, load_len, load_dest), Fclose. THERE IS NO ERROR CHECK AT ALL -- a failed Fopen yields handle<0 and the Fread simply fails; the disc-presence handshake is done separately by probe_disc. | a0 = an asset_file_table record: Fopen the name at record+8, Fread record+4 bytes to the address at record+0, Fclose.  # ctx — called with a0 = a record at 0x10378/0x11214/0x11278 and nowhere else; body not read.

fn 0x10c4c probe_disc
cmt 0x10c4c Disc-presence probe. Ignores its caller's a0: it always Fopens the name inside file_rec_sprites_cru ("A\SPRITES.cru") and stores the full LONGWORD result in disc_probe_result, closing the handle again if it opened. Callers read disc_probe_result: >=0 means disc A is in the drive, <0 means it is not -- which is how the "INSERT DISC B" prompts wait for disc A to be REMOVED.

fn 0x10d92 check_cheat_name
cmt 0x10d92 Called from hiscore_name_entry the moment the third initial is confirmed, with a0 pointing at the LAST of the three characters. First it spins up to 5000 times waiting for key bit 0 (keypad '4', scancode 0x6b) to be held -- so a cheat only arms while that key is down. Then a0 -= 2 and the three characters are matched against cheat_name_table, four bytes per row: three name codes plus a handler index, terminated by 0x64. On a hit it sets 0x176d4 (nothing ever reads it), jsr's cheat_handler_table[index], and copies the four characters of title_word_spam over title_word_easy -- which is how the title's "MODE EASY" becomes "MODE SPAM" once a cheat has been entered.

fn 0x14218 acia_ikbd_isr
cmt 0x14218 IKBD/MIDI ACIA interrupt, installed at $118 (68000 vector 70 = MFP channel 6). Reads $fffffc02. 0xFE = joystick-0 packet header -> re-point $118 at acia_joy0_byte and return; 0xFF = joystick-1 header -> re-point at acia_joy1_byte. Anything else is a KEY: store the raw byte at key_last_scancode, clear bit 7 of it (make vs break) and compare it against the eight watched codes at key_watch_scancodes, doing `bset d0,key_bits` on a make and `bclr d0,key_bits` on a break. Every path ends `bclr #6,$fffffa11` (clear the MFP in-service bit) then rte. The game therefore OWNS the ACIA vector: TOS's own IKBD parser never runs, which is why tos_joyvec_handler is dead.
