fn 0x1003c level2_scenery_effect
cmt 0x1003c Level-2 only scenery animation, gated by level_number == 2 (level2_scenery_effect_gate @ 0x10bc8) and by a SIGNED level_distance in [0x8a2, 0x9c6]. fn 0x1030e enter_title
cmt 0x1030e Enter the title screen: title_just_entered = 0xff, set_palette_black, and if level0_assets_loaded is still clear, set it and load_level_assets(0) first. Falls into title_attract_loop either way.
fn 0x10332 load_level_assets
cmt 0x10332 Load the five files a stage needs, for level d0 (0..4). First it PATCHES THE FILENAMES: five bytes from level_bank_digits + 5*d0 are written into byte 6 of each of the four "A\HSC_n.DAT" names (0x16354/0x16368/0x1637c/0x16390) and into byte 7 of "A\LEVEL1.MAP" (0x1633f), so one record set serves every stage. Then a per-level sequence of load_file calls interleaved with disc-swap prompts (all of which are patched out in this build -- see the PATCH section). Bank digits per level: 0->HSC 0,1,2,3 + LEVEL1; 1->4,5,6,7 + LEVEL2; 2->8,9,A,B + LEVEL3; 3->0,1,3,B + LEVEL4; 4->8,C,3,7 + LEVEL5. | d0.w = level number. Copies the five ASCII digits from level_asset_digit_table into the HSC and LEVEL filenames in asset_file_table, then loads bank 0, the map and banks 1..3, inserting the "insert disc B" prompt on the levels whose banks are not on disc A.

fn 0x104f2 title_attract_loop
cmt 0x104f2 The title/attract screen. Blacks the palette, scroll_y = 0, scroll_phase = 0x1e, rebuilds map_ptr/map_ptr_start from the map header, prescrolls prescroll_count+1 frames, then loops: sound_cmd(4) and wait for the sound module's byte at +30 to go non-zero. Exits with `rts` when joystick-1 FIRE is pressed and new_hiscore_pending is clear (the caller then starts a game); branches to hiscore_show_entry_screen (0x106f2) when new_hiscore_pending is set -- which is NOT a way out: that routine falls into hiscore_name_entry, whose every arm ends `bra.w $10720` -> `bra.w $10594`, i.e. title_frame_step, the very next thing this loop does. So the branch leaves and returns once a frame and the loop has ONE exit of its own, the `rts` at 0x105a6. Joystick-1 LEFT copies title_word_easy into title_mode_word and sets hard_mode = 0, RIGHT copies title_word_hard and sets hard_mode = 1; both trigger the sound at 0x121e6. The attract text cycles on attract_page_timer, which reloads from attract_page_reload: below 0xc8 -> text_hall_of_fame, below 0x226 -> text_credits, otherwise text_publisher.
fn 0x10594 title_frame_step
cmt 0x10594 One attract frame: scroll_step(), then loop back into title_attract_loop's poll while scroll_y < 0xbb8 (3000); at 3000 the whole attract restarts. Reached only by branches from inside title_attract_loop -- it is not a separate callee.
fn 0x10698 build_text_display_list
cmt 0x10698 Interpret a text script into the 6-byte-per-record display list at a1. The script is [start_x.b][start_y.b] -- BYTE moves into d1/d2, so the high byte of each is the caller's, and every caller clears them as longwords first -- then a byte stream: 0x00 = advance x by 8 (a space), 0x04 = advance x by 0x40, 0x05 = newline (y += 8, x = 0), 0x06 = x += the word at ADDRESS 0x40 (low memory, _etv_timer's high word -- almost certainly a bug), 0x09 = end, anything else = emit {x.w, y.w, code.b, enable=1} and advance x by 8. All the x/y arithmetic is word-wide, so a column near 0xffff wraps rather than carrying. Character codes: 0xab..0xc4 = 'A'..'Z', 0xc5..0xce = '0'..'9', 0xcf = space, 0xd0+ = HUD glyphs.
proto 0x10698 script@A0 dest@A1
fn 0x106f2 hiscore_show_entry_screen
cmt 0x106f2 Build the hall-of-fame page: hiscore_reset_last_digit, render text_hall_of_fame into the display list, and if name_entry_done is clear also render text_enter_your_name. Falls through into hiscore_name_entry.
fn 0x10724 game_over_hiscore_check
cmt 0x10724 Game over. hard_mode = 0, hiscore_rank = 5; convert score_bcd to characters and compare against hiscore_table entry 5 (the 6th, lowest). If the score does not beat it, clear new_hiscore_pending and jump to 0x15754 (restart at init_new_game). Otherwise walk UP the table while the score beats entry (rank-1), shift the beaten entries down one slot each with hiscore_shift_entry_down, copy the six score characters into entry+16, set new_hiscore_pending = 0xff and name_entry_timeout = const_words_0123 (0), and jump to 0x15754. TWO FAULTS. (1) `move.b #$f0,5(a1)` @ 0x1073e is a DEAD STORE -- it stamps a glyph above every digit into score_digits[5] so a tie would compare high, and the very next instruction (bcd3_to_digits) rewrites all six digits over it, so a tie LOSES. (2) The rank walk has no floor: a score above entry 0 leaves rank = 0 and the next compare reads entry -1, 22 bytes BELOW the table, inside text_hall_of_fame's script (muls.w sign-extends). It stops there only because those bytes are positive and the compare is signed. Entered by `adda.l #$40,a7 / bra` from read_player_input (the F10 abort) and from 0x13c90 (lives exhausted) -- both unwind rather than return.

fn 0x108c0 hiscore_reset_last_digit
cmt 0x108c0 Write '0' (0xc5) into byte 21 -- the last score character -- of all six hiscore_table entries. Called once, from hiscore_show_entry_screen.
fn 0x108f8 digits6_compare
cmt 0x108f8 Compare six character digits at a6 against the six at a5+16 (a5 is a hall-of-fame entry, so +16 is its score field). SIGNED byte compare (cmpm.b + blt/bgt), which matters only where an operand is not a digit glyph -- every digit is >= 0xc5 and so negative. Returns d0 = -1 if a6 is lower, OR IF ALL SIX ARE EQUAL (the dbf falls into the same `move.w #$ffff,d0`), and +1 if a6 is higher at the first differing digit. d0 is a WORD, so the caller's high half survives. Both a5 and a6 are advanced past the compared bytes.

fn 0x10916 hiscore_name_entry
cmt 0x10916 Three-character name entry into hiscore_table + 22*hiscore_rank + 11. On first entry (name_entry_done clear) the three characters are filled with 0xcf (space). Joystick-1 right increments the character (wrapping 0xcf->0xab), left decrements (wrapping 0xab->0xcf), fire advances name_entry_cursor. On the third fire it calls check_cheat_name and sets name_entry_done; after that name_entry_timeout counts down and, at -1, resets everything (new_hiscore_pending=0, name_entry_cursor=0, name_entry_done=0, name_entry_timeout=0x32) and the attract loop resumes.

The tail block's final store is `move.b #$1,(a1)` with no postincrement, so a1 comes back at slots+35, one short of the row's end.

fn 0x10bd8 score_add_10000
cmt 0x10bd8 The ninth award wrapper: a1 = 0x15a4b, so the three `abcd -(a1)` operands are 0x15a48..0x15a4a = 01 00 00 = 10000. Note the nine wrappers are NOT contiguous -- 0x10bc8 sits between the eighth and the ninth and is an unrelated level-2 hook.
fn 0x10bec score_add_bcd
cmt 0x10bec Add a 3-byte BCD value to score_bcd: `lea $15a2d,a0` then three `abcd -(a1),-(a0)`, so the addends are the three bytes BELOW a1 and the accumulator is 0x15a2a..0x15a2c. a1 therefore points ONE PAST the value; the nine wrappers below pass score_award_values + 3, +6, ... +27, selecting 50/100/200/250/500/1000/3000/5000/10000 in order. The FIRST abcd's carry-in is the 68000's X flag on entry -- an input, since neither the wrapper's movem.l nor its lea touches the condition codes -- and the LAST abcd's carry-out is the X the caller's next instruction sees. The carry out of the top byte is discarded, so the score WRAPS at 999999.
proto 0x10bec end_of_value@A1
fn 0x10bfa load_file
cmt 0x10bfa Load one file. a0 -> an 8-byte record [dest.l][length.l] followed by the NUL-terminated DOS path; both longwords are RELOCATED in the image, so at run time the first is an absolute address. Copies them to load_dest / load_len, GEMDOS Fopen(name, mode 2) -> load_file_handle, Fread(handle, load_len, load_dest), Fclose. THERE IS NO ERROR CHECK AT ALL -- a failed Fopen yields handle<0 and the Fread simply fails; the disc-presence handshake is done separately by probe_disc. NOTE the record's LENGTH may exceed the file's: A\LEVEL1.MAP asks for 0x1388 bytes to 0x16432, which would reach 0x177ba -- over load_dest, load_len and load_file_handle themselves -- and only the short read (the file is 3,664 bytes) stops it. A level map that filled its record would leave this routine closing a handle it had just overwritten.
proto 0x10bfa record@A0
fn 0x10c4c probe_disc
cmt 0x10c4c Disc-presence probe. Ignores its caller's a0: it always Fopens the name inside file_rec_sprites_cru ("A\SPRITES.cru") and stores the full LONGWORD result in disc_probe_result, closing the handle again if it opened. Callers read disc_probe_result: >=0 means disc A is in the drive, <0 means it is not -- which is how the "INSERT DISC B" prompts wait for disc A to be REMOVED. The negative arm is UNVERIFIABLE off target: the differential harness's TOS model refuses an Fopen of a name nothing staged rather than answering -1, so only the success path can be run (recreate/STATUS.md, "Unpinned on target").

fn 0x10d92 check_cheat_name
cmt 0x10d92 Called from hiscore_name_entry the moment the third initial is confirmed, with a0 pointing at the LAST of the three characters. First it spins up to 5001 times (move.w #$1388,d7 + dbf) waiting for key bit 0 (keypad '4', scancode 0x6b) to be held -- so a cheat only arms while that key is down. Then a0 -= 2 and the three characters are matched against cheat_name_table, four bytes per row: three name codes plus a handler index, terminated by 0x64. On a hit it sets 0x176d4 (nothing ever reads it), jsr's cheat_handler_table[index], and copies the four characters of title_word_spam over title_word_easy -- which is how the title's "MODE EASY" becomes "MODE SPAM" once a cheat has been entered. BUG: the mismatch arm after TWO matched glyphs (@ 0x10df8) rewinds a0 by ONE, not two, so later rows are matched against name[1..] and a match can run past the end of the three-character name.

fn 0x11636 vbl_handler
cmt 0x11636 Vertical-blank handler, installed straight into vector $70 (NOT a _vblqueue slot). `addq.l #1` on the LONGWORD vbl_tick -- unguarded, so it wraps to 0 rather than saturating -- then `lea $58944,a0 / jsr 38(a0)` into the loaded sound module, restores d0-d7/a0-a6 and ends `jmp $1164e.l`. THAT JMP IS SELF-DESCRIBING: its operand longword lives at 0x11650, the image ships it pointing at the jmp itself, and boot_init overwrites it with TOS's old $70 vector -- so the handler chains to TOS rather than rte'ing. Nothing else in the image touches $ff8800/$ff8802, so all music and all effects go through that one call.
