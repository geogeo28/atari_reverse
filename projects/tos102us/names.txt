# names.txt — TOS 1.02 (US) ROM, TOS102US.img, 196,608 B, dated 1987-04-22.
#
# ADDRESS CONVENTION: a Ghidra address here IS a REAL ROM/machine address. The ROM is
# imported raw at 0xFC0000 (where it is decoded on the ST), not at the 0x10000 image
# base the .PRG projects use, and it carries no relocation table — every absolute
# operand in the image already resolves. RAM addresses ($0..$C9FF), the I/O page
# ($FFFF8000..) and the cartridge port ($FA0000..) are memory blocks RomLoader creates,
# so a `var` line can name an address the file does not contain.
#
# Format: `fn`/`var`/`cmt`/`param`/`proto`, one directive per line, ONE `cmt` per address
# (ApplyNames sets rather than appends — a second cmt silently deletes the first).
# A trailing `# ctx` marks a name taken from a dispatch-table position or a published ABI
# rather than from a read of the body; those are the refinable ones.
#
# PROVENANCE of the dispatch-table names below: every table was located by reading the
# dispatcher that indexes it (addresses in COMPONENTS.md), and the selector->name mapping
# is the published TOS ABI. Three independent cross-checks came out clean, which is why
# the numbering is trusted: every GEMDOS selector the ABI leaves undefined lands on the
# one stub at 0xfc933e and every defined one does not; the same holds for the AES's gaps
# against 0xfe64a6 and the XBIOS's against 0xfc0670; and XBIOS Physbase/Logbase/Getrez/
# Setscreen/Random/Vsync were confirmed from their bodies (they touch $ffff8201/$44e/
# $ffff8260/$4ba/$466).

# The SAME registers through their 24-bit addresses, which is how TOS itself reaches the
# blitter and, in the VDI's colour calls, the palette: the ST decodes $00FFxxxx and $FFFFxxxx
# to one device, and an absolute-long operand costs the same either way. Ten blitter `lea`
# sites (0xfc47be, 0xfc4852, 0xfc48b6, 0xfc4936, 0xfca20a, 0xfca5ca, 0xfcee6a, 0xfcf9be,
# 0xfcfccc, 0xfd0674) and four palette sites (0xfd2e32, 0xfd2e66, 0xfd2ee4, 0xfd2f06) —
# RomLoader creates the IO_ALIAS block so these resolve to a label instead of to nothing.

# ---------------------------------------------------------------------------
# Boot chain, interrupt handlers and the trap/exception entry points.
# Each name is from a body read; the install site is given in the comment.
# ---------------------------------------------------------------------------
fn 0xfc0030 os_reset
cmt 0xfc0030 Reset entry (OS header +0x04). sr := 0x2700, RESET, probe the cartridge magic 0xFA52235F at $FA0000, then memory sizing, vector table, hardware init, AUTO folder, desktop.
fn 0xfc0b50 os_exception_bombs
cmt 0xfc0b50 Exception handler installed into $08..$FC by the loop at 0xfc0334 with the vector number in the ignored top address byte. Dumps d0-a7 to proc_regs ($384), the PC to $3c4 and the USP to $3c8, then draws the bombs.
fn 0xfc07ce os_rte_stub
cmt 0xfc07ce Bare rte. Installed at 0xfc0340 into $14 (divide by zero), at 0xfc034c into the seven autovectors $64..$7c, and at 0xfc0366 into $88 (trap #2) until the GEM dispatcher replaces it.
fn 0xfc06c8 hbl_handler
cmt 0xfc06c8 Vector $68, the horizontal blank: raises the interrupted frame's IPL to 3 when it was 0 (ori.w #$300 on the saved SR) and rte's -- the ROM's guard against a program that unmasked HBL. src/bios/hbl.c; recreate/test/test_bios_hbl.py. SHIPS as the ROM's own bytes, recreate/src/bios/isr.S (byte-pinned).
fn 0xfc06de vbl_handler
cmt 0xfc06de Vector $70, the vertical blank: _frclock++ then the vblsem semaphore (re-read before release), _vbclock++; the monitor follower (GPIP bit 7 vs defshiftmd, a SIGNED cmp.b #2, writes $ff8260 from sshiftmd); the palette from colorptr (16 words to $ff8240, colorptr cleared); the screen base from screenpt copied INTO _v_bas_ad and then to $ff8203/$ff8201 (screenpt NOT cleared); the cursor blink; the _vblqueue walk over nvbls slots; the floppy VBL behind flock; the screen-dump hook on _dumpflg. src/bios/vbl.c; recreate/test/test_bios_vbl.py. SHIPS as the ROM's own bytes, recreate/src/bios/isr.S (byte-pinned); the C named here is its twin, which no entry calls.
fn 0xfc07ee etv_critic_default
cmt 0xfc07ee Default critical-error handler (moveq #-1,d0; rts), installed at 0xfc0386 into etv_critic ($404).
fn 0xfc07fc trap_dispatch_common
cmt 0xfc07fc Shared BIOS/XBIOS trap tail: switch to savptr ($4a2) for the register frame, read the selector, bounds-check it against the table's first word, index longwords; a NEGATIVE entry is a pointer to a RAM vector (hdv_bpb/hdv_rw/hdv_mediach) rather than a routine.
fn 0xfc07f8 bios_trap13
cmt 0xfc07f8 trap #13 (BIOS) entry, installed at 0xfc036a into $b4. Loads a0 with the BIOS table at 0xfc0846 and falls into trap_dispatch_common.
fn 0xfc07f2 xbios_trap14
cmt 0xfc07f2 trap #14 (XBIOS) entry, installed at 0xfc0372 into $b8. Loads a0 with the XBIOS table at 0xfc0878 and falls into trap_dispatch_common.
fn 0xfc4f6e gemdos_trap1
cmt 0xfc4f6e trap #1 (GEMDOS) entry, installed at 0xfc4e5e into $84. Serves Super (0x20) inline, otherwise builds the process register frame off p_run ($87ce) and calls gemdos_dispatch.
fn 0xfc94e4 gemdos_dispatch
cmt 0xfc94e4 GEMDOS function dispatcher (compiled C: link a6, args at 8(a6)). Rejects a selector above 0x57 with EINVFN (-32), else indexes the 6-byte records at 0xfd307a (handler longword + argument-descriptor word).
fn 0xfc4ebc gem_trap2_boot
cmt 0xfc4ebc trap #2 (GEM) entry installed at 0xfc4e72 into $88 before the AES exists: d0 == 0x73 calls the VDI at 0xfc9f9e, d0 == -1 returns that address in d0, d0 == 0 takes the abort path, anything else chains to the previous vector saved at 0x16d6.
fn 0xfe3ea6 gem_trap2_aes
cmt 0xfe3ea6 trap #2 (GEM) handler, installed at 0xfe3c78 into $88 once the AES is up: d0.w == 0xC8/0xC9 enters the AES at 0xfe65aa on the running PD's UDA stack (UDA+0 := 1, UDA+66 := USP, UDA+70 := SSP, SP := UDA+62; D1-A6 parked on the USER stack — A0 already holds the USP by then, so a program gets A0 back as its user stack pointer, not its own); d0.w == 0 is Pterm(0) through trap #1, never back; anything else chains to the vector saved at 0x8c2a. recreate: aes_rom_trap2 (src/aes/trapdoor.S), the ROM's bytes.
fn 0xfc9f9e vdi_entry
cmt 0xfc9f9e VDI entry (GEM trap #2, d0 = 0x73). Copies the caller's five-array parameter block from d1 into the VDI's own RAM at 0x299e, copies ptsin to 0x19da (2n in a WORD, capped unsigned at 1024 words: $8000 points copies nothing, $8200 exactly 1024 with no cap; 512 written into the caller's contrl[1] before the copy), calls vdi_dispatch, gives the caller's count back through LINEA_CONTRL re-read, and returns the word at 0x171e in D0.w (D0's high word is the dispatched function's). Ships as src/vdi/entry.S's vdi_rom_entry.
fn 0xfca9f6 vdi_dispatch
cmt 0xfca9f6 VDI opcode dispatcher. Clears contrl[2]/[4] and VDI_RESULT, finds the workstation by handle (first match wins: v_opnvwk inserts a duplicate handle AHEAD of the older one; opcodes 1 and 100 skip the lookup; an unknown handle returns having called nothing), loads the attribute state (21 copies + MULTIFILL + MONO_STATUS, in a pinned order), then indexes opcodes 1..39 in the table at 0xfd372c and 100..131 in the table at 0xfd37c8; any other opcode still loads the workstation.
fn 0xfe65aa aes_entry
cmt 0xfe65aa aes_entry(selector.w, 0.w, parameter block) — AES entry, reached only by value from the trap #2 handler (movea.l #,a0 at 0xfe3f00; jsr (a0)). link a6,#-4; selector 200: aes_marshal(block); then dsptch for 200 and 201 alike; clr.w (sp) — the program's D0.w — and the way out 0xfe3f08, which never returns: the Line-F return at 0xfe65c2 is dead. recreate: aes_rom_entry (src/aes/trapdoor.S), the ROM's stream with its three call words as jsr.
fn 0xfe5d9c aes_dispatch
cmt 0xfe5d9c AES opcode dispatcher (opcode.w, global, int_in, int_out, addr_in), ONE routine to 0xfe64e5: moveq #1,d6, then sub #10 / cmp #115 / bhi bounds the opcode UNSIGNED to 10..125 and jumps through the table at 0xfef834 to one of 68 arms or the default (fm_show 'Bad Function #', -1); every arm leaves by the ladder of tst.w (sp)+ to move.w d6,d0. An arm with no move.w d0,d6 answers 1 whatever its routine did (32 of them); graf_mkstate answers -1. Verified in C: recreate/src/aes/gemsuper.c.
fn 0xfe64e6 aes_marshal_arrays
cmt 0xfe64e6 AES parameter-block marshalling (C core: aes_marshal): link a6,#-66; copies contrl (4 words), intin (contrl[1] words) and addrin (2*contrl[3] words) into ONE 62-byte frame (addrin[2] at -62, intout[7] at -54, intin[16] at -40, contrl at -8), calls aes_dispatch through Line-F $f2b0, stores its answer in intout[0], copies intout (contrl[2] words) back, and for the COPIED opcode 112 stores $944c through addrout. NO COPY IS BOUNDED: a count past its array runs into the arrays above it, and past the frame into the saved A6 and the return address (intin > 20 words / addrin > 15 longwords: the ROM returns through the caller's words; intout > 27 words hands them back). Verified in C: recreate/src/aes/gemsuper.c.
fn 0xfc9f0c linea_dispatch
cmt 0xfc9f0c Line-A handler, installed at 0xfc037a into $28. Reads the faulting $aXXX word, masks the low 12 bits, bounds-checks it to 15 and jumps through the 16-entry table at 0xfc9f4a, advancing the stacked PC past the word. Clobbers D2/A2/A6 across the handlers it serves ($a007 adds 76 to A6, $a00d loads it). $fc9f0c..$fc9ffb (with $a000 and vdi_entry) ships as src/vdi/entry.S.
fn 0xfee8c2 linef_handler
cmt 0xfee8c2 GEM Line-F call handler, copied into a Malloc'd buffer and installed into $2c by the AES init at 0xfd9f4a. An EVEN $fXXX word is a one-word call through the 658-entry table at 0xfee900 (index = the low 12 bits as a byte offset); an ODD one is a return (unlk a6; rts, plus a movem mask of (op & 0x0ffe) * 4).
fn 0xfd9eca gem_entry
cmt 0xfd9eca gem_entry (the GEM entry point the memory-usage parameter block at 0xfefff4 names; entered by the BIOS as a program, never called, never returns): USP := $898e; Mshrink(basepage, text+data+bss+256); Super(sp) — the same stack the supervisor's, top $8994; $c924 := p_env; $8904..$890c laid; $2c's high byte non-zero -> Malloc(100), the Line-F handler and 38 bytes of its table ($fee8c2..$fee925) copied, $2c := the copy; jsr rom_rsc_init ($fee4de); $8992 := 1; $97fe := 0; LOOP $fd9f72: jsr size_theglo ($fee800), THEGLO cleared (move.w d1,(a0)+ / dbmi d0), justretf -> $947a, the tick glue -> $947e, ub_trampoline -> $8c32, A6 := UDA0's stack top, UDA+62 := A6, SP := A6, jsr gem_main ($fda062), bra LOOP. On target: src/aes/gemstart.S (byte-pinned but seven relocated operands). THE $2c TEST IS MADE ONCE: the loop's bra ($fd9fc4) goes back to $fd9f72, past it — its skip arm is taken by no pass of a session (no machine; held by the pin and a labelled craft). VERIFIED AT ITS CHECKPOINTS ON THE OUR-BOOT MACHINE (band 5 wave 4, slice B: the blob laid at the pre-init stop and entered here — its own instructions' cycles the ROM's, 98,920)
fn 0xfc0688 memory_size_probe   # ctx
cmt 0xfc0688 Called from the reset path at 0xfc0050/0xfc00e8 through the a6 return-address convention (lea ret,a6 / bra sub / jmp (a6)) rather than by bsr.

cmt 0xfc8b44 Input status for a BIOS device: -1 if GEMDOS's own typeahead queue holds a record for it ($756c[device]), else BIOS Bconstat. Cconis and Cauxis are this routine over their own standard handle.
cmt 0xfc8c12 The poll EVERY GEMDOS output makes before it writes a byte, and the only place flow control lives. Bconstat once; then read keys and classify: ^C resets the queue and Pterm(-32)s, ^S sets a hold and re-reads (blocking) until ^Q, ^X resets the queue and queues itself, anything else is queued while the count is < 80 and answered with a BEL when it is not. The key is the LOW BYTE (and.l #255) but the whole longword is queued.
cmt 0xfc8d4e Empty one device's typeahead queue: count := 0 and both pointers back to $83c0 + device * 320. ^C and ^X are its two callers.
cmt 0xfc8d96 One character to a device: the poll above, BIOS Bconout, then the per-device COLUMN COUNTER at $68f4 - +1 for a character >= 32 (SIGNED word compare), 0 for CR, -1 for BS, unchanged for everything else (LF included). cmt 0xfc8e88 ...and with a control code echoed as '^' and the letter code|$40 (two columns). TAB goes to $fc8e3c instead; DEL ($7f) is not a control code to this test and prints as itself. The Cconrs line editor's echo, where Cconin's is the raw $fc8d96.

cmt 0xfc90e2 Cconws' loop: each byte SIGN-EXTENDED into the character word (move.b / ext.w), so a byte with bit 7 set is negative to $fc8d96's signed compare and does NOT advance the column counter. cmt 0xfc910c CR, LF, then N spaces - how Cconrs' ^U and ^R get back to the column the line began in.
cmt 0xfc9152 Rub out the last character: re-walk the first length-1 characters adding up how wide each PRINTS (TAB to the next multiple of 8, a control code 2, anything else 1) and then send BS/space/BS until the column counter has come back to that width. cmt 0xfc9226 The Cconrs line editor. cmt 0x756c byte[3]: how many records are queued ahead of the reader on each standard device (max 80).
cmt 0x83c0 The three typeahead queues: 80 four-byte Bconin records each, 320 bytes apart.
cmt 0x8830 long[3]: where the next queued record comes OUT.

cmt 0xfc5a98 THE GEMDOS buffer cache. Two BCB lists at _bufl ($4b2) — [0] FAT, [1] dir AND data — MRU to the front, LRU at the tail. The region is arithmetic on the record: shifted down to its cluster and compared with the root directory's own first cluster; below it the FAT, at or above it a negative record is the root directory and a non-negative one is data. A hit asks Mediach with b_bufdrv and TRUNCATES the answer to a word: 0 stands, 1 flushes and re-reads the hit IN PLACE, 2 is E_CHNG and a longjmp.
