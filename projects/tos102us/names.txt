# names.txt — TOS 1.02 (US) ROM, TOS102US.img, 196,608 B, dated 1987-04-22.
#
# ADDRESS CONVENTION: a Ghidra address here IS a REAL ROM/machine address. The ROM is
# imported raw at 0xFC0000 (where it is decoded on the ST), not at the 0x10000 image
# base the .PRG projects use, and it carries no relocation table — every absolute
# operand in the image already resolves. RAM addresses ($0..$C9FF), the I/O page
# ($FFFF8000..) and the cartridge port ($FA0000..) are memory blocks RomLoader creates,
# so a `var` line can name an address the file does not contain.
#
# Format: `fn`/`var`/`cmt`/`param`/`proto`, one directive per line, ONE `cmt` per address
# (ApplyNames sets rather than appends — a second cmt silently deletes the first).
# A trailing `# ctx` marks a name taken from a dispatch-table position or a published ABI
# rather than from a read of the body; those are the refinable ones.
#
# PROVENANCE of the dispatch-table names below: every table was located by reading the
# dispatcher that indexes it (addresses in COMPONENTS.md), and the selector->name mapping
# is the published TOS ABI. Three independent cross-checks came out clean, which is why
# the numbering is trusted: every GEMDOS selector the ABI leaves undefined lands on the
# one stub at 0xfc933e and every defined one does not; the same holds for the AES's gaps
# against 0xfe64a6 and the XBIOS's against 0xfc0670; and XBIOS Physbase/Logbase/Getrez/
# Setscreen/Random/Vsync were confirmed from their bodies (they touch $ffff8201/$44e/
# $ffff8260/$4ba/$466).

# The SAME registers through their 24-bit addresses, which is how TOS itself reaches the
# blitter and, in the VDI's colour calls, the palette: the ST decodes $00FFxxxx and $FFFFxxxx
# to one device, and an absolute-long operand costs the same either way. Ten blitter `lea`
# sites (0xfc47be, 0xfc4852, 0xfc48b6, 0xfc4936, 0xfca20a, 0xfca5ca, 0xfcee6a, 0xfcf9be,
# 0xfcfccc, 0xfd0674) and four palette sites (0xfd2e32, 0xfd2e66, 0xfd2ee4, 0xfd2f06) —
# RomLoader creates the IO_ALIAS block so these resolve to a label instead of to nothing.

var 0x00ff8a20 hw_blitter_src_xinc
var 0x00ff8a28 hw_blitter_endmask1

# ---------------------------------------------------------------------------
# Boot chain, interrupt handlers and the trap/exception entry points.
# Each name is from a body read; the install site is given in the comment.
# ---------------------------------------------------------------------------
fn 0xfc0030 os_reset
cmt 0xfc0030 Reset entry (OS header +0x04). sr := 0x2700, RESET, probe the cartridge magic 0xFA52235F at $FA0000, then memory sizing, vector table, hardware init, AUTO folder, desktop.
fn 0xfc0b50 os_exception_bombs
cmt 0xfc0b50 Exception handler installed into $08..$FC by the loop at 0xfc0334 with the vector number in the ignored top address byte. Dumps d0-a7 to proc_regs ($384), the PC to $3c4 and the USP to $3c8, then draws the bombs.
fn 0xfc07ce os_rte_stub
cmt 0xfc07ce Bare rte. Installed at 0xfc0340 into $14 (divide by zero), at 0xfc034c into the seven autovectors $64..$7c, and at 0xfc0366 into $88 (trap #2) until the GEM dispatcher replaces it.
fn 0xfc06c8 hbl_handler
cmt 0xfc06c8 Vector $68, the horizontal blank: raises the interrupted frame's IPL to 3 when it was 0 (ori.w #$300 on the saved SR) and rte's -- the ROM's guard against a program that unmasked HBL. src/bios/hbl.c; recreate/test/test_bios_hbl.py.
fn 0xfc06de vbl_handler
cmt 0xfc06de Vector $70, the vertical blank: _frclock++ then the vblsem semaphore (re-read before release), _vbclock++; the monitor follower (GPIP bit 7 vs defshiftmd, a SIGNED cmp.b #2, writes $ff8260 from sshiftmd); the palette from colorptr (16 words to $ff8240, colorptr cleared); the screen base from screenpt copied INTO _v_bas_ad and then to $ff8203/$ff8201 (screenpt NOT cleared); the cursor blink; the _vblqueue walk over nvbls slots; the floppy VBL behind flock; the screen-dump hook on _dumpflg. src/bios/vbl.c; recreate/test/test_bios_vbl.py.
fn 0xfc07ee etv_critic_default
cmt 0xfc07ee Default critical-error handler (moveq #-1,d0; rts), installed at 0xfc0386 into etv_critic ($404).
fn 0xfc07fc trap_dispatch_common
cmt 0xfc07fc Shared BIOS/XBIOS trap tail: switch to savptr ($4a2) for the register frame, read the selector, bounds-check it against the table's first word, index longwords; a NEGATIVE entry is a pointer to a RAM vector (hdv_bpb/hdv_rw/hdv_mediach) rather than a routine.
fn 0xfc07f8 bios_trap13
cmt 0xfc07f8 trap #13 (BIOS) entry, installed at 0xfc036a into $b4. Loads a0 with the BIOS table at 0xfc0846 and falls into trap_dispatch_common.
fn 0xfc07f2 xbios_trap14
cmt 0xfc07f2 trap #14 (XBIOS) entry, installed at 0xfc0372 into $b8. Loads a0 with the XBIOS table at 0xfc0878 and falls into trap_dispatch_common.
fn 0xfc4f6e gemdos_trap1
cmt 0xfc4f6e trap #1 (GEMDOS) entry, installed at 0xfc4e5e into $84. Serves Super (0x20) inline, otherwise builds the process register frame off p_run ($87ce) and calls gemdos_dispatch.
fn 0xfc94e4 gemdos_dispatch
cmt 0xfc94e4 GEMDOS function dispatcher (compiled C: link a6, args at 8(a6)). Rejects a selector above 0x57 with EINVFN (-32), else indexes the 6-byte records at 0xfd307a (handler longword + argument-descriptor word).
fn 0xfc4ebc gem_trap2_boot
cmt 0xfc4ebc trap #2 (GEM) entry installed at 0xfc4e72 into $88 before the AES exists: d0 == 0x73 calls the VDI at 0xfc9f9e, d0 == -1 returns that address in d0, d0 == 0 takes the abort path, anything else chains to the previous vector saved at 0x16d6.
fn 0xfe3ea6 gem_trap2_aes
cmt 0xfe3ea6 trap #2 (GEM) entry installed at 0xfe3c78 into $88 once the AES is up: d0 == 0xC8/0xC9 enters the AES at 0xfe65aa, d0 == 0 terminates via GEMDOS Pterm(0), anything else chains to the vector saved at 0x8c2a.
fn 0xfc9f9e vdi_entry
cmt 0xfc9f9e VDI entry (GEM trap #2, d0 = 0x73). Copies the caller's five-array parameter block from d1 into the VDI's own RAM at 0x299e, copies ptsin to 0x19da (2n in a WORD, capped unsigned at 1024 words: $8000 points copies nothing, $8200 exactly 1024 with no cap; 512 written into the caller's contrl[1] before the copy), calls vdi_dispatch, gives the caller's count back through LINEA_CONTRL re-read, and returns the word at 0x171e in D0.w (D0's high word is the dispatched function's). Ships as src/vdi/entry.S's vdi_rom_entry.
fn 0xfca9f6 vdi_dispatch
cmt 0xfca9f6 VDI opcode dispatcher. Clears contrl[2]/[4] and VDI_RESULT, finds the workstation by handle (first match wins: v_opnvwk inserts a duplicate handle AHEAD of the older one; opcodes 1 and 100 skip the lookup; an unknown handle returns having called nothing), loads the attribute state (21 copies + MULTIFILL + MONO_STATUS, in a pinned order), then indexes opcodes 1..39 in the table at 0xfd372c and 100..131 in the table at 0xfd37c8; any other opcode still loads the workstation.
fn 0xfe65aa aes_entry
cmt 0xfe65aa AES entry (GEM trap #2, d0 = 0xC8). Reached from gem_trap2_aes; calls the AES dispatcher through the Line-F call table.
fn 0xfe5d9c aes_dispatch
cmt 0xfe5d9c AES opcode dispatcher: sub #10 / cmp #115 bounds the opcode to 10..125, then jumps through the table at 0xfef834.
fn 0xfe64e6 aes_marshal_arrays
cmt 0xfe64e6 AES parameter-block marshalling: copies the caller's contrl/intin/addrin arrays into local frames, calls aes_dispatch through Line-F $f2b0, then copies intout/addrout back.
fn 0xfc9f0c linea_dispatch
cmt 0xfc9f0c Line-A handler, installed at 0xfc037a into $28. Reads the faulting $aXXX word, masks the low 12 bits, bounds-checks it to 15 and jumps through the 16-entry table at 0xfc9f4a, advancing the stacked PC past the word. Clobbers D2/A2/A6 across the handlers it serves ($a007 adds 76 to A6, $a00d loads it). $fc9f0c..$fc9ffb (with $a000 and vdi_entry) ships as src/vdi/entry.S.
fn 0xfee8c2 linef_handler
cmt 0xfee8c2 GEM Line-F call handler, copied into a Malloc'd buffer and installed into $2c by the AES init at 0xfd9f4a. An EVEN $fXXX word is a one-word call through the 658-entry table at 0xfee900 (index = the low 12 bits as a byte offset); an ODD one is a return (unlk a6; rts, plus a movem mask of (op & 0x0ffe) * 4).
fn 0xfd9eca gem_entry
cmt 0xfd9eca GEM entry point named by the memory-usage parameter block at 0xfefff4.
fn 0xfc0688 memory_size_probe   # ctx
cmt 0xfc0688 Called from the reset path at 0xfc0050/0xfc00e8 through the a6 return-address convention (lea ret,a6 / bra sub / jmp (a6)) rather than by bsr.

The store into $eb0 is ordinary RAM and survives the call, so after any GEMDOS call that longword names the instruction after whichever `jsr $fc4eac` ran last. cmt 0xfc7f1a GEMDOS record pool: a ZEROED record of size class d0.w (class*8 words = class*16 bytes) - popped off p_root[class] if one waits, else cut from the arena as class*8+1 words with the class word written below it. 0 when the arena is spent, which is TOS 1.02's "out of memory descriptors".
cmt 0xfc7f9c GEMDOS record pool: push a record back onto p_root[class], the class read out of the WORD BELOW the record; the record's first longword becomes the chain link.
cmt 0xfc886a GEMDOS allocator core (amount 8(a6), MPB 12(a6)): NEXT-FIT from mp_rover, wrapping through the MPB read as the descriptor before the first. Answers the descriptor, or the largest free m_length for amount = -1, or 0. The block keeps m_start and takes the request's length; the REMAINDER gets a new descriptor and the block's place in the free list. The rover is left at the block's predecessor, or at mp_mfl when that predecessor is the MPB.
cmt 0xfc89dc GEMDOS free-list insert, sorted by m_start ascending, with coalescing: FORWARD first (md swallows its successor) then BACKWARD (the predecessor swallows md), so three blocks can become one and two descriptors go back to p_root[1], the successor's first. cmt 0x7e8e GEMDOS's own memory parameter block, $7e8e..$7e99: mp_mfl here, mp_mal $7e92, mp_rover $7e96. GEMDOS's init hands this address to BIOS Getmpb ($fc935e); Malloc/Mfree/Mshrink reach it absolutely. The free list is kept sorted by m_start; the allocated list is not.

cmt 0xfc5a98 THE GEMDOS buffer cache. Two BCB lists at _bufl ($4b2) — [0] FAT, [1] dir AND data — MRU to the front, LRU at the tail. The region is arithmetic on the record: shifted down to its cluster and compared with the root directory's own first cluster; below it the FAT, at or above it a negative record is the root directory and a non-negative one is data. A hit asks Mediach with b_bufdrv and TRUNCATES the answer to a word: 0 stands, 1 flushes and re-reads the hit IN PLACE, 2 is E_CHNG and a longjmp. A miss takes the LAST empty buffer in the list, else the tail.

cmt 0xfc5c9a One 11-byte FCB pattern against one directory entry. cmt 0xfc5d28 "name.ext" into eleven padded FCB bytes. `*` fills the rest of its field with `?`; a stem past eight is truncated and the rest thrown away up to the next `.`, `\` or NUL — a skip stopped by neither `*` nor space, unlike the copy loop.
