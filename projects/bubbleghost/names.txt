# BUBBLE GHOST (Atari ST, ERE Informatique 1987 / Accolade 1988; code Christophe Andreani).
# Binary: GHOST.PRG ships wrapped in a protection-keyed stream cipher (notes/loader.md);
# tools/depack_bubbleghost.py produces bin/GHOST_PLAIN.PRG -- an Alcyon/DRI C small-model
# program, text 0xe8ca, data 0x2f4, bss 0x6650, 9 relocs. ghidra_proj holds bin/GHOST_RT.PRG:
# the same program in its RUN-TIME layout, text 0x14f1a (= code + bss), data 0x2f4, bss 0.
# Ghidra address = image offset + 0x10000. Run-time layout is [TEXT][BSS][DATA] with a4 on
# the BSS/DATA boundary: a4+n = DATA (Ghidra address = n + 0x14f1a + 0x10000 = n + 0x24f1a),
# a4-n = globals.
#
# 132 fn, 182 var, 130 cmt. Sections below: entry/crt0, front end + GEM/VDI binding,
# file I/O, gameplay (rooms/objects/ghost/bubble/collision), blitters, HUD/score, sound
# engine, C library, globals by subsystem, tables, plate comments.
#
# A trailing '# ctx' marks a name inferred from call context rather than a confirmed body
# read (on fn/var/param lines ApplyNames strips everything from the first '#'; cmt text
# is taken whole). Evidence is in notes/anchors.md, notes/frontend.md, notes/gameplay.md
# and notes/sound_engine.md.

Both results are written BACK into the two argument slots on the stack -- the caller pops one for the quotient and one for the remainder, which is how itoa_padded gets a digit and the next value from two consecutive calls. | A ZERO DIVISOR EXECUTES `divu.w #0,d0` DELIBERATELY, raising the 68000's zero-divide exception. | A DIVISOR OF 0x80000000 HANGS: its magnitude cannot be represented, so `neg.l` leaves it negative, the alignment loop shifts the 1 out of the top and never reaches divisor >= dividend again.
cmt 0x15970 c_lmul(long a, long b): signed 32x32 multiply built from three 16x16 mulu partial products; the result is written back into the second argument slot.
cmt 0x159dc c_lseek(short fd, long offset, short whence): GEMDOS Fseek (0x42); on a negative result it re-probes the file with two more Fseeks to clamp against the real end and retries. Returns the new offset or -1.
cmt 0x15af2 c_morecore(short want): round want up to a multiple of 0x418, ask gemdos_malloc_or_fail for that many 6-byte granules, and link the block onto c_malloc's free list. The bottom of the c_malloc allocator.
cmt 0x15b54 c_malloc(short size): first fit over the circular free list rooted at c_malloc_freelist (a4-25770). Every block carries a six-byte header -- a `next` longword and a size in 6-BYTE GRANULES, header included -- and the caller gets the address just past it. The request becomes 1 + (size+5)/6 granules. An empty root self-initialises to c_malloc_sentinel (0x1ea74) and falls straight through to c_morecore. An exact-size block is unlinked whole; a larger one is SHORTENED and the TAIL is what the caller gets, so the roving pointer can stay where it is.
cmt 0x15bfe c_free(void *p): link the block at p-6 back into the ascending circular list and coalesce with the neighbour on each side. The search walks from the roving pointer until the block sits strictly between a node and its successor, or until it reaches the list's WRAP -- the one node whose successor is not above it, where an address below every node and one above every node are both "in the gap". Every compare is a SIGNED longword compare, which is faithful for an arena inside the image and would not be for one above 0x80000000.
cmt 0x15cae c_setfdmode(long fd_and_mode): record (fd, mode) in the first free slot of the 76-entry fd_mode_table. Mode 0x2000 is the binary flag c_write later reads back.
cmt 0x15cfa c_clearfdmode(short fd): zero every fd_mode_table entry whose fd matches. Called by c_close.
cmt 0x15d36 c_getfdmode(short fd): linear search of fd_mode_table; returns the recorded mode word (0 = text) for the fd. | A MISS READS PAST THE TABLE. The loop tests, steps, and stops when the cursor reaches the end, so an exhausted search leaves a0 one entry beyond slot 75 and the `move.w 2(a0),d0` that follows reads 0x1e93e + 0x130 + 2 = 0x1ea70 = the HIGH WORD OF c_malloc_freelist — zero until something has allocated, and the arena's high word afterwards. | It also leaves a1 at 0x1ea6e (= c_errno's address) unconditionally, which is what c_read's top-up Fread then parks in trap_saved_a1.
cmt 0x15e3c xbios_trap: the same six instructions over trap #14. Every XBIOS call in the program goes through here; the C library itself never calls it.
cmt 0x15e58 gemdos_trap: park a1, a2 and the trampoline's own return address in trap_saved_a1/a2/ret, POP the return address off the stack so the caller's selector word lands at 2(sp) where TOS reads it, trap #1, restore a1/a2, push the return address back, rts. Those three longwords are its whole image effect -- and the return address is a CALL-SITE constant, so the slot says which wrapper trapped. NOTE that a1/a2 are not always the caller's: c_malloc holds the free list's roving cursor in a2 when it reaches c_morecore, and c_read's top-up Fread holds its write cursor in a2 and c_errno's address in a1 (left there by c_getfdmode).
cmt 0x15e74 c_fmt_integer(short conv, char **out, long value): radix 10 for 'd'/'u', 8 for 'o', 16 for 'x'; emits the sign for 'd' and the digits into *out, advancing it.
cmt 0x15fe0 c_fmt_float(long conv_and_flags, char **out, double value, short precision): the e/f/g formatter; calls c_fcvt twice to get the digit string and the decimal exponent.
cmt 0x161b8 c_fmt_getnum(char **p): read a run of ASCII digits from *p, advancing it, and return the value. Used for printf field width and precision.
cmt 0x1620c c_doprnt(char *out, void *args): the format engine. Walks the format string, parses flags/width/precision (c_fmt_getnum), and dispatches d/u/o/x to c_fmt_integer, e/f/g to c_fmt_float, plus c and s; writes into the caller's buffer and returns the length.
cmt 0x16496 c_vfprintf(FILE *f, void *args): c_doprnt into a 256-byte stack buffer, then c_fputs it. Returns c_doprnt's length -- so any single printf longer than 256 bytes smashes this frame.
cmt 0x164c2 c_printf(char *fmt, ...): c_vfprintf(c_stdout, &args). Exactly one call site in the whole game: main's LOW REZ message.
cmt 0x164d8 c_sprintf(char *buf, char *fmt, ...): c_doprnt straight into the caller's buffer.
cmt 0x164ee c_fputs(char *s, FILE *f): c_putc every byte until the NUL.
cmt 0x16518 c_conin(short fd): the cooked console reader. fd -32000 (CON:) buffers a whole line in conin_buffer with echo -- backspace erases, CR appends LF and echoes CR LF, Ctrl-C calls c_exit, Ctrl-Z appends and marks EOF. fd -0x7d01 (AUX:) reads one raw character. Anything else returns -1.
cmt 0x1667c c_read(short fd, char *buf, short len): fd <= 0x8300 (SIGNED) is the console, served by c_conin. Otherwise GEMDOS Fread into buf, then c_getfdmode: a NON-ZERO mode (binary) returns the count as it stands. | TEXT MODE walks what was read dropping every 0x0d and TOPS THE BUFFER UP with further Freads until it has packed `len` bytes or hit EOF, so a text read of n bytes can issue many traps and can move the file cursor well past what it returns. Two narrowings are the original's: the pointer differences are `ext.l` of a WORD, and the "did Fread fail" test is a WORD compare of the result.
cmt 0x167c8 gemdos_malloc_or_fail(short size): GEMDOS Malloc (0x48), returning -1 rather than 0 when it fails. c_morecore's only supplier -- distinct from gemdos_malloc at 0x15c82, which is stdio's.

cmt 0x1683e c_strlen(char *s): byte scan to the NUL.
cmt 0x16868 c_unlink(char *path): GEMDOS Fdelete (0x41); 0 on success, -1 otherwise. Only c_open calls it, for the O_TRUNC-ish path.
