# Wonder Boy in Monsterland (Activision/Sega, 1989) -- SWB.PRG name map
#
# ###########################################################################
# ## LOAD BASE IS 0x3F8, *NOT* THE WORKSPACE DEFAULT 0x10000.              ##
# ###########################################################################
# SWB.PRG's entry stub copies the image from file offset 8 down to absolute
# $400 and jumps there, so the program is position-DEPENDENT at run time and
# its own absolute operands are "image offset + $3F8". Loading at 0x10000
# leaves every absolute reference dangling, which is why Ghidra recovered only
# 57 functions; at 0x3F8 it recovers 186+.
#
#   runtime = image_offset + 0x3F8          (image_offset = file_offset - 28)
#   runtime = old_ghidra_addr - 0xFC08      (converting a 0x10000-based note)
#
# Bootstrap with:
#   bash tools/headless.sh projects/wonderboy/ghidra_proj wonderboy \
#        projects/wonderboy/bin/disk1/AUTO/SWB.PRG 0x3f8 projects/wonderboy/decomp.c
# run.sh has been corrected to pass 0x3f8, so it is safe again -- but it still
# re-imports and wipes the DB, so iterate with reapply.sh.
#
# See notes/architecture.md for the evidence, the region table and the memory map.
#
# The linear listing out/wonderboy_dis.txt is regenerated at the same base with
#   python3 tools/prg_dis.py projects/wonderboy/bin/disk1/AUTO/SWB.PRG --base 0x3f8
# (its banner states the base). Any listing produced WITHOUT --base is at base 0,
# i.e. every address in it is runtime-0x3F8 and will not match this file.
#
# Untagged names were confirmed by reading the disassembled body.
# "# ctx" marks a name inferred from call context only.
#
# Every address a cmt cites is the INSTRUCTION's address, never the offset of the
# operand inside it -- so a cite can be looked up in out/wonderboy_dis.txt as it
# stands. (`move.l #imm,$a098.l` at $ff14 carries its $a098 at $ff1a; the cite is
# $ff14.)
#
# NEVER `proto` a register-returning routine: ApplyNames' `proto` forces a VOID
# return, so a directive on a routine whose result is a register would record
# something false. Put the register map in that routine's `cmt` instead.

# ---------------------------------------------------------------------------
# Bootstrap / startup  (see architecture.md "Startup sequence")
# ---------------------------------------------------------------------------
cmt 0x3f8 GEMDOS entry. Only these first 8 bytes stay here; 0x3fa is `jmp startup_relocate_and_run` (one of the image's 3 relocations).
fn 0x217d8 startup_relocate_and_run
cmt 0x217d8 The only OS call in the whole program: GEMDOS Super($214d8+loadbase) to enter supervisor mode with a fresh SSP, then `move.w #$2700,sr` (IPL7), then copy $84f6 longwords (=$213d8 bytes) from image+8 down to absolute $400 and `jmp $400`. NOTE: this stub runs at the GEMDOS load address, so its address here ($217d8) is an artefact of the $3f8 base -- at run time it lives at basepage_text+$213e0.
fn 0x400 cold_start
cmt 0x400 First instruction executed at the final runtime address. move.w #$2700,sr; palette entry 15 := $077; jmp sys_save_tos_stack.
fn 0xe482 sys_save_tos_stack
cmt 0xe482 Stashes the TOS-supplied A7 at $f8b8 -- the only recorded way back to TOS -- then falls through to hw_init_vectors.
fn 0xf8bc hw_init_vectors
cmt 0xf8bc A7 := $80000 (top of a 512 KB ST); $70 (autovector 4 = VBL) := vbl_handler; $118 (MFP channel 6 = ACIA) := ikbd_acia_handler; MFP IERB/IMRB bit 6 set; sr := $2300 (IPL3, so VBL and ACIA get through); jmp init_ikbd.
fn 0xe48c init_ikbd
cmt 0xe48c 8-byte link in the boot chain: `bsr ikbd_disable_mouse` then `bra.w $e4e6` (boot_continue). That is its whole body -- the video/palette/screen-clear/MFP/VBL work the boot performs lives at 0xe4e6, which Ghidra folds into show_data_disk_prompt (0xe494), not into this function.
fn 0xf8f0 ikbd_disable_mouse
cmt 0xf8f0 Polls the ACIA status at $fffffc00 for TX-empty (bit 1) and writes IKBD command $12 ("disable mouse") to $fffffc02. Uses abs.w addressing ($fc00.w), which is why a longword scan for $fffffc00 does not see it.
cmt 0xe4e6 Boot continuation (Ghidra folds this into the 632-byte function at 0xe494 because show_data_disk_prompt falls through into it at $e4e4; it is a separate entry point, reached by `bra.w` from init_ikbd). video_set_lowres_50hz, clear_palette, clear_both_screens, mask MFP timer A/B (IERA/IMRA := 0), install vbl_handler, sr := $2300, arm copylock_arm_flag ($e51e), then load_resource_by_index(0 = TITLESCR.RAD -> $49800).
fn 0x4a0 game_main_loop
cmt 0x4a0 The main game loop: an unconditional `do { ... jsr flip_screen } while(1)` -- $508 is `bra.s $4a0` and there is no exit. Entered by `jmp $4a0.w` from $e708 (after the boot's first stage load) and from $f8b4. Body: two leading bsr's, then a block that runs only when $66e == 0 (jsr $e032 / $b346 / $dbc0 / $882, and $882 is `joy1_latch_edge` + the object-list pass at $8d0), then $8dfe, $7522, $8e66, $82f8, $50a, $8f02, a block gated on $a30 ($ff42), $bd8a, and finally flip_screen.
fn 0x638 game_unpause_on_key_release
cmt 0x638 54 bytes, RE-CHECKED AND STILL REJECTED (recreate/STATUS.md batch 12) -- it SPINS on memory no instruction in its own body writes. `tst.w $66e.l / beq.w $66c` returns at once unless the pause word is set, and `cmpi.b #$19,$879.l / bne.w $66c` returns unless key_last_scancode still holds the press; only then does `cmpi.b #$99,$879.l / bne.s $64e` wait for the RELEASE code ($19 | $80) that ikbd_acia_handler will store, and the payload behind it is `clr.b $879`, `clr.w $66e` and `move.b #$ff,text_request` -- i.e. unpause and dismiss the box. The pause is SET by the mirror-image arm at $60e inside $53e, which spins on the same byte and posts message $34 instead. THE SPIN IS WHY IT CANNOT BE PORTED, not the payload: nothing changes memory while an oracle run is in flight, so the checkpoint is unreachable and a wider register window or a `stop_pc` does not help. REGISTERED with terms -- trigger = a kit capability to schedule a memory poke at an instruction count or a PC; home = tools/recreate_kit, in emu.run. ONE `bsr` caller, game_main_loop's at $4a0.

# Interrupt handlers

fn 0x716 vbl_handler
cmt 0x716 Vertical-blank handler (autovector 4, installed at $70 by hw_init_vectors and again at $e506). movem d0-a6; addq.w #1,vbl_counter; `lea snd_stub_00,a0 / jsr 14(a0)` = the music tick; then if floppy_idle_timer is non-zero, decrement it and call floppy_deselect_drives ($6268 -- NOT $6242) when it reaches 0. This is the only periodic tick in the program: MFP timers A and B are masked off at boot. (Earlier note said `fn 0x716` could not apply because Ghidra folded the bytes into flip_screen. That was wrong: flip_screen is [$694..$6f7]+[$702..$709] and getFunctionContaining($716) was empty. The real blocker was a bogus 4-byte `pointer` auto-defined at $714..$717 -- Ghidra read `0000 48e7` = $48e7, an in-image address -- which made disassemble() a no-op. ApplyNames now clears defined data under an `fn` address first.)
fn 0x754 ikbd_acia_handler
cmt 0x754 MFP channel 6 (ACIA) handler, installed at $118. Reads the IKBD byte from $fffffc02. $FE/$FF are the IKBD joystick-report headers: it re-vectors $118 to ikbd_joy0_byte_handler / ikbd_joy1_byte_handler so the NEXT interrupt captures the data byte, then returns. Anything else is a key scancode, decoded into the key bitmap at key_bits.
fn 0x83a ikbd_joy0_byte_handler
cmt 0x83a One-shot: stores the IKBD data byte in joy0_state, clears MFP ISRB bit 6, restores ikbd_acia_handler at $118, rte.
fn 0x858 ikbd_joy1_byte_handler
cmt 0x858 One-shot: stores the IKBD data byte in joy1_state, clears MFP ISRB bit 6, restores ikbd_acia_handler at $118, rte.
var 0x876 joy0_state
var 0x877 joy1_state
cmt 0x877 IKBD joystick-1 report byte. Bit 7 = fire. The idiom `clr.b $877 / tst.b $877 / bpl.s * / tst.b $877 / bmi.s *` that appears all over the boot path is "wait for fire pressed, then released" -- it is the "press a key" wait, NOT a keyboard flag. (Naming it from position alone would have got this wrong.)
var 0x878 key_bits
cmt 0x878 One byte, 8 key flags. ikbd_acia_handler stores the raw scancode at key_last_scancode ($879), strips bit 7 (the key-release flag) and then compares the code against the 8 bytes of key_watch_scancodes ($87a..$881), bset'ing (press) or bclr'ing (release) the matching bit of THIS byte via `lea $879,a0 / lea -1(a0),a1`. Nothing in the image ever reads $878, and key_watch_scancodes is all zeroes in the image with no writer, so no scancode can ever match: the whole keyboard path is vestigial and the game is joystick-only. (Scanned for abs.l, abs.w and pc-relative d16 references to $878/$87a -- zero of each.)
var 0x879 key_last_scancode
cmt 0x879 The last raw IKBD scancode byte, stored by ikbd_acia_handler before the release bit is stripped. Unlike key_bits this IS read: `cmpi.b #imm,$879.l` at $560, $574, $5da, $5e6, $60e, $642, $64e...
var 0x87a key_watch_scancodes
cmt 0x87a 8 bytes, the scancodes ikbd_acia_handler folds into key_bits (index = bit number). All zero in the image and never written -- see key_bits.
fn 0x682 joy1_newly_pressed
cmt 0x682 `move.b joy1_prev,d0 / move.b joy1_current,d1 / eor.b d1,d0 / and.b d1,d0 / rts` -- returns in d0 the bits that are set in joy1_current and were NOT set last frame, i.e. a rising-edge mask over the joystick byte. Note it reads $8b3/$8cf, not key_bits. REGISTER INTERFACE: no arguments, and the result is d0's LOW BYTE ONLY -- every instruction is a `.b` op, so the caller's own top 24 bits of d0 pass through untouched. Eight call sites reach it (bsr.w from $e6c/$ef0/$1220/$526e, jsr from $6fde/$dc00/$dc34/$dc6e); only the three inside FUN_0000dbc0 ($dc00/$dc34/$dc6e) are in recovered code, and those three take the result as a BYTE -- the other five are unexamined. The reconstruction reproduces the whole longword anyway (recreate/src/input.c, g_joy1_newly_pressed) because that is what the differential compares. d1 is clobbered.
fn 0x88c joy1_latch_edge
cmt 0x88c `move.b joy1_current,joy1_prev / move.b joy1_state,joy1_current` -- shifts the joystick byte one frame down the pipeline so joy1_newly_pressed can diff them. Called from $882 once per frame.
var 0x8b3 joy1_prev
cmt 0x8b3 The joystick-1 report byte as of the PREVIOUS frame. It physically occupies the NUL terminator of the "Wheres Saigon??????" filler string -- the filler is inert but this byte inside it is live.
var 0x8cf joy1_current
cmt 0x8cf The joystick-1 report byte latched for THIS frame (copied from joy1_state by joy1_latch_edge). Occupies the NUL terminator of the "I Dunno Im not Psychic!!!!!" filler string.

fn 0x694 flip_screen
cmt 0x694 Swaps screen_front/screen_back, then writes the new front buffer's bits 16-23 and 8-15 to $ffff8201/$ffff8203. Waits on vbl_counter and clears it. Then `not.w frame_toggle` -- a 0 <-> $ffff TOGGLE, not a decrement -- and, if flash_timer is non-zero, decrements it and writes $777 (white) to $ffff8240, or 0 (black) on the frame it reaches 0. So flip_screen paints colour 0 for the duration of the flash: a visible full-screen colour-0 flash the differential oracle cannot see (palette writes are off-image). READ THE LISTING, NOT decomp.c, FOR THIS ONE: Ghidra reports `pcode error at $6f8: Unable to resolve constructor` and emits only `do {} while (vbl_counter < 1); do {} while(true);` -- the whole toggle/flash tail is dropped. Pre-existing, not caused by the $714 retype.
var 0x712 frame_toggle
cmt 0x712 Word, inverted by flip_screen every frame ($0000 <-> $ffff). Read as a boolean at $4f08, $8e40, $8ed4.
var 0x714 flash_timer
cmt 0x714 Word countdown decremented by flip_screen; while non-zero colour 0 is forced to $777, and it is cleared to black on expiry. Read at $23b8. NOT a pointer -- auto-analysis typed $714..$717 as one, which is what used to block `fn 0x716`.
fn 0x70a return_to_tos
cmt 0x70a `movea.l tos_stack_save,a7 / rts` -- restores the A7 sys_save_tos_stack captured at boot and returns to GEMDOS. No jsr/jmp/bsr/bra anywhere in the image targets it and no longword or abs.w operand holds $70a, so as shipped it is unreachable: the game never exits.
var 0x74a vbl_counter
var 0x74c screen_front
cmt 0x74c Longword = address of the buffer currently being displayed; $74d/$74e are its high/mid bytes, written straight to $ffff8201/$ffff8203. Initialised to $078000.
var 0x750 screen_back
cmt 0x750 Longword = address of the buffer being drawn into. Initialised to $070000.
fn 0xf906 video_set_lowres_50hz
cmt 0xf906 $ffff8260 := 0 (low res, 320x200x16); screen base := $070000; $ffff820a := 2 (50 Hz PAL).
fn 0xf926 clear_both_screens
cmt 0xf926 clr.l over $3f40 longwords from $70000 -- i.e. $70000..$7FD00, exactly the two 32000-byte screen buffers back to back.
fn 0xf938 copy_screen
cmt 0xf938 d0 := $1f3f then falls through to copy_longs: copies $1f40 longwords = 32000 bytes = one screen, a0 -> a1.
fn 0xf93c copy_longs
proto 0xf93c copy_longs src@A0 dst@A1 count_minus_1@D0
cmt 0xf93c move.l (a0)+,(a1)+ / dbf d0. Copies d0+1 longwords. Entered directly by callers that preset d0.
fn 0xf944 set_palette
proto 0xf944 set_palette src@A0
cmt 0xf944 Copies 8 longwords (16 ST palette words) from a0 to $ffff8240.
fn 0xe7f4 clear_palette
cmt 0xe7f4 clr.l over all 16 palette registers at $ffff8240.

# Masked planar sprite blitters, $8fce..$989c -- 12 routines behind 3 jump tables.
# The earlier region table called $8fce..$a271 DATA on "0 bsr, 0 movem". That test
# is the wrong one here: this block has 16 `rts` in 1127 words (14.2/kW, squarely in
# the CODE band) and 8 `dbf`, but it is leaf code entered only through a pointer
# table, so it contains no bsr and no movem at all. Correct split:
#   CODE $8fce..$989c (2254 B)   DATA $989c..$a271 (2517 B, 88.3% zero, 0 idioms)
# Dispatcher at $8f9a: `lea blit_table_mid,a2 / tst.w d4 / bmi -> blit_table_left /
# cmp.w #$b0,d4 / bge -> blit_table_right / lsl.w #2,d2 / adda.w d2,a2 /
# movea.l (a2),a2 / jsr (a2)`. d4 = X, d2 = width class 0..3.
# All 12 bodies are unrolled `and.w mask,(a1) / or.w plane,(a1)+` x4 per word column,
# `swap` for the second half-longword, then `lea <160 - bytes_advanced>(a1),a1` to
# step one 320px 4-plane scanline, `dbf d7`. The lea constant gives the width:
#   146 -> 2 words (32 px), 138 -> 3 (48 px), 130 -> 4 (64 px), 122 -> 5 (80 px).
# ---------------------------------------------------------------------------
var 0x989c blit_table_mid
cmt 0x989c 4 longwords: $9594 $95f6 $9692 $9774 -- the unclipped blitters, widths 2/3/4/5 words. Selected when 0 <= d4 < $b0.
var 0x98ac blit_table_left
cmt 0x98ac 4 longwords: $8fce $908c $91be $936c -- the left-edge clip preludes, widths 2/3/4/5. Selected when d4 < 0.
var 0x98bc blit_table_right
cmt 0x98bc 4 longwords: $8fe4 $90b4 $91f8 $93b6 -- the right-edge clip preludes, widths 2/3/4/5. Selected when d4 >= $b0.
var 0x9966 blit_clip_mask
cmt 0x9966 Byte written by the eight clip preludes (values 1,2,3,7,...) and tested with `btst #n,$9966` inside the clipped blit bodies to skip individual 16-pixel word columns. 38 references, all inside $8fce..$989c.
fn 0x8fce blit_clip_left_w2
cmt 0x8fce Left-edge prelude for the 32-pixel blitter: if d4 < -16 the sprite is fully off-screen -- `subq.w #6,a5` (unwind the caller's object pointer) and rts; otherwise blit_clip_mask := 1 and `bra.w $900a`, the shared clipped 2-word body. blit_clip_right_w2 branches to the same body. The four `blit_clip_*_w2..w5` pairs are all built this way.
fn 0x8fe4 blit_clip_right_w2
cmt 0x8fe4 Right-edge prelude for the 32-pixel blitter: d4 >= $f0 -> fully off-screen, rts; $e0 <= d4 < $f0 -> blit_clip_mask := 2; d4 < $e0 -> blit_clip_mask := 3. Then `bra.w $900a` into the shared clipped 2-word body ($900a..$908a).
fn 0x908c blit_clip_left_w3
fn 0x90b4 blit_clip_right_w3
cmt 0x90b4 Shared clipped 3-word body at $90ec..$91bc.
fn 0x91be blit_clip_left_w4
fn 0x91f8 blit_clip_right_w4
cmt 0x91f8 Shared clipped 4-word body, ends at $936a.
fn 0x936c blit_clip_left_w5
fn 0x93b6 blit_clip_right_w5
cmt 0x93b6 Shared clipped 5-word body, ends at $9592.
fn 0x9594 blit_sprite_w2
cmt 0x9594 Unclipped masked blit, 2 words = 32 pixels wide, d7+1 rows. Mask in d1, the four bitplanes in d2-d5, all pre-rotated by `ror.l d6,dn` for the sub-word X shift; `lea 146(a1),a1` per row.
fn 0x95f6 blit_sprite_w3
cmt 0x95f6 Unclipped masked blit, 3 words = 48 pixels; `lea 138(a1),a1` per row.
fn 0x9692 blit_sprite_w4
cmt 0x9692 Unclipped masked blit, 4 words = 64 pixels; `lea 130(a1),a1` per row.
fn 0x9774 blit_sprite_w5
cmt 0x9774 Unclipped masked blit, 5 words = 80 pixels; `lea 122(a1),a1` per row. Ends at $989a, immediately before blit_table_mid. KNOWN ISSUE: this is the only function in the program that ExportDecompC cannot emit -- Ghidra's decompiler process dies on it every run (not a timeout; the 60 s limit is never reached), so decomp.c carries `// <decompile failed: ... 00009774 ...>` here. The function itself is defined and named correctly in the DB; read it in the listing instead. The other 11 blitters decompile fine, so the trigger is probably its length (296 bytes of fully unrolled straight-line and/or-blitting).

# ---------------------------------------------------------------------------
# Raw floppy: WD1772 FDC + DMA driver.  NO GEMDOS/BIOS/XBIOS IS USED.
# ---------------------------------------------------------------------------
cmt 0x6118 --- Raw FDC/DMA driver. Real extent $5e3e..$64f0 (code) + $64f0..$6528 (state) -- NOT $6118..$64f0: disk_check_signature ($5e3e), disk_load_file ($5e7c) and its FAT helpers ($5f06, $5f76, $5fc4, $604a, $6068, $6092, $60da) all sit below $6118, and fdc_restore ($6408) calls $645e/$646c/$64ea above it. rad_depack ends at $5e3a, immediately below. Registers: $ffff8604 = FDC data/access, $ffff8606 = DMA mode/status, $ffff8609/860b/860d = DMA base address high/mid/low, $ffff8800/8802 = PSG (drive + side select via port A), $fffffa01 bit 5 = MFP GPIP FDC-done. Driving the controller directly is what lets the game read the protection sectors (IDs 11/12 on cylinders 0-4) that no GEMDOS/BIOS/XBIOS call can address. THIS function is the track-read core: $6120 computes the DMA end bound as `(11 - sector) * 512 + <DMA address counter read back>` into fdc_dma_end_track; $6164 writes a sector count of 13 to the DMA sector-count register ($ffff8606 := $90) and then FDC command $90 = Read Sector with m=1 (multiple record), so one command streams the track and fdc_wait_irq_bounded aborts it on the address bound -- i.e. 10 data sectors per track, which is exactly a disk whose sector IDs 11 and 12 are the extra protection sectors. Up to fdc_retry_count attempts; failure returns -3. (Ghidra also invented a misaligned FUN_0000615a two bytes inside the `move.w #$190,$ffff8606` at $6154 -- an artefact, ignore it.)
fn 0x624c psg_set_drive_select
proto 0x624c psg_set_drive_select bits@D0
cmt 0x624c PSG register 14 (port A) read-modify-write: keeps bits 3-7, replaces bits 0-2 with d0. Bit 0 = side select, bit 1 = drive A select*, bit 2 = drive B select* (both active LOW).
fn 0x6242 floppy_select_drive_a
cmt 0x6242 d0 := 5 = %101 -> side 1, drive A SELECTED (bit 1 low), drive B deselected; clears floppy_idle_timer; falls through to psg_set_drive_select. This SELECTS a drive at the start of a disk operation -- it is not the idle routine. Two callers, both `bsr.w`: disk_check_signature ($5e48) and disk_load_file ($5e8e). vbl_handler calls floppy_deselect_drives instead.
fn 0x6268 floppy_deselect_drives
cmt 0x6268 Saves d0/d1, d0 := 7 = %111 -> both drive-select lines high = ALL DRIVES DESELECTED (motor off), calls psg_set_drive_select, restores. This is the real idle routine: its only caller is vbl_handler ($73e) once floppy_idle_timer expires.
var 0x64f2 floppy_idle_timer
cmt 0x64f2 Frame countdown, decremented by vbl_handler. floppy_unwind_return arms it with $96 (150 frames ~ 3 s at 50 Hz); on expiry vbl_handler calls floppy_deselect_drives.
fn 0x6278 fdc_dma_read_addr
cmt 0x6278 Reads the DMA address counter back out of $ffff8609/860b/860d into fdc_dma_addr_readback.
var 0x64fc fdc_dma_addr_readback
cmt 0x64fc Where fdc_dma_read_addr parks the hardware DMA address counter, so the transfer can be resumed from exactly where it stopped. Read at $6038 and by fdc_dma_restore_readback.
fn 0x62c0 fdc_dma_restore_readback
cmt 0x62c0 `move.l fdc_dma_addr_readback,d0 / bra fdc_dma_set_addr+2` -- reprograms the DMA address registers from the READ-BACK counter, as opposed to fdc_dma_restore_addr ($62c8) which uses the last address the driver PROGRAMMED (fdc_dma_addr).
fn 0x6298 fdc_dma_set_addr
proto 0x6298 fdc_dma_set_addr addr@A0
cmt 0x6298 Stores a0 in fdc_dma_addr and writes it to $ffff8609 (bits 16-23), $ffff860b (8-15), $ffff860d (0-7).
fn 0x62b8 fdc_dma_set_addr_to_dirbuf
cmt 0x62b8 Same as fdc_dma_set_addr but with the address taken from fat_dir_buffer.
fn 0x62c8 fdc_dma_restore_addr
cmt 0x62c8 Re-writes the DMA address registers from the saved fdc_dma_addr.
fn 0x62d0 fdc_wait_irq
cmt 0x62d0 Spins up to 600000 iterations on $fffffa01 bit 5 (MFP GPIP, FDC/HDC done, active low). On timeout: fdc_deselect_regs then floppy_unwind_return.
fn 0x6308 fdc_wait_irq_bounded
cmt 0x6308 fdc_wait_irq plus a per-iteration read-back of the DMA address counter, aborting early once it reaches fdc_dma_end_transfer ($6504) or fdc_dma_end_track ($6508). This is how a transfer of unknown length is bounded. On the 600000-iteration timeout it issues fdc_force_interrupt and unwinds with -1.
var 0x6504 fdc_dma_end_transfer
cmt 0x6504 Longword: the DMA address at which the whole requested transfer is complete (programmed address + byte count). Written at $5fe4, $6016, $60ba, $60f8; tested by fdc_wait_irq_bounded.
var 0x6508 fdc_dma_end_track
cmt 0x6508 Longword: the DMA address at which the current TRACK's data run ends -- `(11 - sector) * 512` added to the live DMA counter at $6120. Tested by fdc_wait_irq_bounded so the multiple-record read stops before sector IDs 11/12.
var 0x6526 fdc_retry_count
cmt 0x6526 Word retry counter. Reloaded with 2 at $6118, $637e, $63c0 and $6488; decremented with `subq.w #1` at $61a8, $63a6, $63f8 and $64da, and the operation is abandoned when it hits 0.
fn 0x63b6 fdc_delay
cmt 0x63b6 `move.w #$2a,d7 / dbf d7,*` = 43 iterations (dbf runs until d7 = -1), not 42 -- the settle delay the WD1772 needs between selecting a register on $ffff8606 and accessing it on $ffff8604.
fn 0x645e fdc_write_data_reg
proto 0x645e fdc_write_data_reg value@D1
cmt 0x645e fdc_delay; move.w d1,$ffff8604; fdc_delay.
fn 0x646c fdc_read_data_reg
cmt 0x646c fdc_delay; move.w $ffff8604,d1; fdc_delay. The read counterpart of fdc_write_data_reg; used to fetch the WD1772 status byte after a command.
fn 0x647a fdc_force_interrupt
cmt 0x647a $ffff8606 := $80 (select the FDC command register) then writes $D0 through fdc_write_data_reg. $D0 is WD1772 Type IV **Force Interrupt** with no interrupt condition, i.e. "abort whatever command is running" -- this terminates a transfer, it does not deselect anything.
fn 0x6408 fdc_restore
cmt 0x6408 d1 := $05 = WD1772 Type I **Restore with verify** (seek to track 0, V=1, 6 ms step): $ffff8606 := $80 then fdc_write_data_reg, then spin on $fffffa01 bit 5 with a $493e0 = 300000 timeout, read the status with fdc_read_data_reg, `bclr #6,d1`, and return it in d7. Ghidra's `/* WARNING: Instruction at 0x6436 overlaps instruction at 0x6434 */` here is a decode artefact of the `bsr.w` displacement word at $6436; there is no self-modifying code in this routine.
fn 0x644e floppy_unwind_return
cmt 0x644e Common exit for the whole floppy stack. Arms floppy_idle_timer with $96, restores the stack pointer disk_load_file saved in $64f8, and returns with d0 as the status -- effectively a longjmp, so an error deep in the driver returns straight to disk_load_file's caller. Error codes seen: -2, -3, -4, -5; d0 >= 0 is success (load_resource_by_index tests with `tst.w d0 / bpl`).

proto 0xe782 load_resource_by_index index@D0 dest@A1

# ---------------------------------------------------------------------------
# THE COPY PROTECTION: a Rob Northen-style trace-decrypting Copylock, $ecba..$f574
#
# This is what the earlier pass filed as "UNKNOWN, entropy 7.73, probably packed".
# It is not packed data. It is a self-decrypting protection blob that single-steps
# itself: an `illegal` instruction vectors into a handler that decrypts exactly the
# next longword before letting the CPU execute it, and re-encrypts it afterwards.
# Consequences: (a) $ed8e..$f540 CANNOT be disassembled statically at all -- no
# scan of this program for addresses, traps, hardware registers or OS calls can see
# inside it; (b) a differential harness hits `jsr copylock_entry` on the FIRST
# resource load of the boot and must either model the decryptor or stub $e7cc/$ecca.
# ---------------------------------------------------------------------------
var 0xe7cc copylock_arm_flag
cmt 0xe7cc Word. `move.w #$ffff,$e7cc` arms it at $e51e (immediately before the TITLESCR.RAD load) and at $e6dc (immediately before the SPRITES.CRU load); load_resource_by_index tests it at $e7b2, calls copylock_entry and clears it at $e7c2. Zero in the image. Stubbing this to 0 is the cheap way to keep a harness out of the Copylock.
var 0xecba copylock_table_ptrs
cmt 0xecba Four longwords -- $f576, $f63f, $f708, $f7d1, the four screen_wipe_order tables. No plaintext instruction references this table or any of its four targets (checked abs.l, abs.w and pc-relative d16), so its reader is inside the encrypted body.
fn 0xecca copylock_entry
cmt 0xecca `moveq #0,d0 / move.l #$ffffffff,d1 / bra.s $ed46`. Called only from load_resource_by_index ($e7bc). Ghidra DID create a function here (FUN_0000ecca, ~96 bytes); the earlier pass concluded "Ghidra created no function in the region" because it filtered functions by START address and this one starts at $ecca, just below the region boundary at $ed2a, while its body reaches to about $ed8e inside it. At $ed46: push a6, `lea $ecd4(pc),a6`, `movem.l d0-a7,(a6)` (the 64-byte register save area), a6 += 64, patch the saved a6, then read the illegal-instruction vector $10, `pea $ed6a(pc)`, install that as $10, and execute `illegal` at $ed68 -- which "returns" to the very next instruction. Pure anti-trace. It then restores $10, saves vectors $8..$27 with `movem.l $8.l,d0-d7 / movem.l d0-d7,(a6)`, installs copylock_trace_decryptor at $10, primes the decrypt cursor, and executes a second `illegal` at $ed8c. Everything after that is ciphertext.
var 0xecd4 copylock_reg_save
cmt 0xecd4 96 bytes of zero-filled scratch: $ecd4..$ed13 = d0-a7 saved by `movem.l d0-a7,(a6)`, $ed14..$ed33 = exception vectors $8..$27 (bus error, address error, illegal, zero divide, CHK, TRAPV, privilege, trace) saved by `movem.l d0-d7,(a6)`. copylock_restore_state puts both back.
var 0xed3e copylock_decrypt_cursor
cmt 0xed3e Two longwords: [0] = the address of the longword currently decrypted in place, [4] = its original ciphertext. The trace handler re-encrypts [0] from [4] before decrypting the next one, so at most one instruction is ever plaintext in memory.
fn 0xee02 copylock_illegal_handler
cmt 0xee02 The smoking gun, and the whole mechanism in twenty instructions. Saves d0/a0/a1; installs $ee3c as the TRACE vector ($24) and copylock_key_check as the PRIVILEGE-VIOLATION vector ($20); then edits the exception frame ON THE STACK -- `addi.l #2,14(sp)` steps the return PC past the `illegal`, `ori.b #7,12(sp)` forces IPL7 in the saved SR so nothing can interrupt, `bchg #7,12(sp)` flips the saved T bit so the CPU returns in single-step mode. Then it takes the frame's PC into a0 and does `move.l -4(a0),d0 / not.l d0 / swap d0 / eor.l d0,(a0)` -- the next longword of the instruction stream is XORed with a key derived from the PREVIOUS (already executed) longword. rte. From here every instruction is decrypted one step ahead of the PC and re-encrypted one step behind it, by the trace handler at $ee3c which does the mirror-image `movea.l (a1),a0 / move.l 4(a1),(a0)` restore first.
fn 0xf542 copylock_restore_state
cmt 0xf542 The plaintext tail. `movem.l d0-d7,$8.l` puts exception vectors $8..$27 back, `movem.l $ecd4(pc),d0-a6` puts the entry registers back, rte.
fn 0xf552 copylock_key_check
cmt 0xf552 Installed at vector $20 (privilege violation) by copylock_illegal_handler. `cmp.l #$b472043f,d0 / beq.s $f562 / cmp.l #$8f25c241,d0 / bne.s $f564 / rts`: two accepted 32-bit key values, either of which returns. Anything else falls into the failure path at $f564 -- `jsr load_resource_by_index / jsr fdc_restore / jsr $6f9e / jmp $6bb8`. d0 is produced inside the encrypted body from the fuzzy protection sectors, so it can never be read statically, and it is not reproducible even dynamically (the fuzzy bytes read back differently on each revolution). This branch is STRUCTURALLY unpinnable: not merely non-deterministic, but written in code that cannot be disassembled at all.
fn 0x6bb8 game_routine_6bb8 # ctx
cmt 0x6bb8 NOT copylock-specific despite being the Copylock failure path's final `jmp` target: four `bra.w` sites in the gameplay code also tail-jump to it ($35c2, $3ff2, $5472, $54a6). Structure only, meaning unidentified: `if ($a32 != 0 && a0 == $9e94) { snd_stub+28; $dfac := $ffff; snd_stub+56 with d0=$19; $b6fe(d0=4) } ; clr.b 18(a0); ...`.
cmt 0xf564 The Copylock failure path. It is also the mystery "seventh call site" of load_resource_by_index that the earlier pass could not resolve: d0/a1 are set up inside the encrypted body, so the file index and destination are unreadable.
var 0xf576 screen_wipe_order_even_odd
cmt 0xf576 201 bytes: a permutation of 0..199 terminated by $ff -- all 100 even lines top-down, then all 100 odd lines bottom-up. One of four scanline orders reached through copylock_table_ptrs. **This block is why the region measured entropy 7.73 and got filed as "packed".** A permutation of 0..199 is maximally entropic BY CONSTRUCTION -- every byte value distinct -- so "high entropy therefore compressed" was never a valid inference here. fn 0x51ac rng_1_to_4_masked

fn 0x68c6 rng_next
cmt 0x68c6 The game's PRNG. Advances three free-running counters modulo $25/$17/$11 ($6932/$6934/$6936), then returns `($ff8209 ^ $b39a) + $6932 + $6934 + $6936` in d0. $ff8209 is the SHIFTER'S VIDEO ADDRESS COUNTER (low byte, the fastest-changing one -- $ff8205/8207/8209 are high/mid/low) -- the only genuine entropy in the mix, and the only hardware access anywhere in the game-logic subsystem. # ---------------------------------------------------------------------------
# BACKGROUND SCROLL ENGINE ($7522..$8228) -- what produces the buffers the
# blitter below copies to the screen. Fifteen routines, no hardware access
# anywhere in the range (the hw scan reports none), and every callee inside it.
#
# The game keeps EIGHT pre-shifted copies of the level background, $5800 bytes
# each, tiling $44000..$70000. Copy N is the same map drawn two pixels further
# left than copy N-1, so a two-pixel horizontal scroll is a change of BUFFER and
# not a redraw, and only the one tile column a scroll uncovers has to be drawn.
# bg_scroll_preshift_rows is the other half of that scheme: it propagates a
# freshly drawn ROW through all eight copies, `rol.l #2` at a time.
#
# The shape is a request queue drained once a frame:
#   game_main_loop -> bg_scroll_run_queue ($7522, the image's only caller)
#     -> bg_scroll_raise_requests ($d28) raises up/down/left/right
#     -> N x bg_scroll_serve_requests ($759a), which dispatches each raised
#        request byte to a serve routine that CONSUMES it
#     -> serve = step (move the position words) + fill (draw the new edge)
# A step with nothing to do does `addq.l #4,(a7)` / `addq.l #8,(a7)` and `rts`,
# returning PAST its caller's `bsr`s to the fill -- so "no movement" and "skip
# the redraw" are one act. Ghidra models none of it (decomp.c shows a bare
# `return`), which is why the skip is stated on every step below.
#
# Verified byte for byte in recreate/: the six HORIZONTAL routines ($75fc,
# $760c, $795e, $79d2, $7c08, $7eb2). The vertical half and the queue above it
# are named here from the same reading and queued in recreate/STATUS.md.
# ---------------------------------------------------------------------------

# Background scroll blitter: the SECOND unrolled blit family, behind a jump
# table -- exactly the failure docs/methodology.md records for $8fce..$989c.
# Found by re-reading the coverage gap the portability measurement admits to
# (recreate/PORTABILITY.md 8.1): $8366..$8dfe was in no Ghidra function at all,
# because the only way in is `movea.l (0,a2,d1.w),a2 / jmp (a2)`.
#
# game_main_loop ($4a0) calls bg_scroll_blit once a frame. It builds
#   a1 = screen_back + $1420                          (destination)
#   a0 = $44000 + bg_scroll_phase*$2c00 + bg_scroll_y*128 + bg_scroll_x*8
#   a2 = bg_scroll_blit_table[bg_scroll_x]            (0..15)
# then splits the 160 destination scanlines around the source buffer's
# vertical wrap: d7+1 rows before it and, if d6 >= 0, d6+1 rows after a
# `lea -$5800(a0),a0` rewind. BOTH HALVES RUN INSIDE THE VARIANT -- the two
# `jmp (a2)` at $8350/$8364 are the two arms of `subi.w #$10,d6 / bpl`, one
# loading d6 = $ffff outright (the window fits: no second half) and the other
# computing d7 and d6 from the ring row, and exactly ONE of them executes per
# call. An earlier reading of this block had them entering the variant twice;
# they do not, and the `tst.w d6 / bpl / rts` inside every variant is what makes
# the second half conditional.
#
# Each variant copies 30 longwords (120 bytes = 240 px of a 4-plane line) per
# scanline out of a 128-byte-wide circular row, then `lea 40(a1),a1` to finish
# a 160-byte screen line. Variant x is the one whose unrolled `move.l (a0)+,(a1)+`
# run is split where byte offset 8*x makes the source row wrap:
#   x=0,1  30 moves, no wrap (8*x + 120 <= 128), then a0 += 8
#   x>=2   (32-2x) moves, `lea -128(a0),a0`, (2x-2) moves, then a0 += 136
#          (the two runs always sum to 30: x=2 -> 28+2, x=8 -> 16+14, x=15 -> 2+28)
# so the 16 bodies tile $83b6..$8dfe exactly, 2 x 154 + 14 x 166 = 2632 bytes.
# ---------------------------------------------------------------------------

Reads the three scroll variables that live in the code hole just above the first variant, picks one of the 16 unrolled copy routines out of bg_scroll_blit_table, and jumps into it. CORRECTED: it enters that routine ONCE, not once per half -- the two `jmp (a2)` at $8350/$8364 are the two arms of `subi.w #$10,d6 / bpl`, and the vertical split is done INSIDE the variant by its own `tst.w d6 / bpl / rts`. fn 0xfa30 bg_build_buffer
cmt 0xfa30 214 bytes, reconstructed in recreate/src/stage.c. Draws the map's visible window -- 11 tile rows of 16 cells -- into pre-shifted copy 0 at $44000, one 128-byte bg_tile_bitmaps bitmap per cell laid down 128 bytes a scanline. a0 = the level map (header and all), a1 = the two words naming the top-left map cell, a6 = the tile bank. THE MAP HEADER IS TWO WORDS: `move.w (a1)+,d0 / move.w (a1)+,d1 / move.w (a0),d2 / mulu.w d2,d1 / add.w d0,d1 / lea 4(a0,d1.w),a0` reads the stride out of the map's own first word and biases past both header words -- the same +4 the collision map's lookup uses, and what WB_MAP_DATA_ROW sat above WB_MAP_ROW_STRIDE for. Three semantics reproduced rather than tidied: the cell index is a WORD and the `lea` SIGN-EXTENDS it, so a start row past $7fff names a cell BELOW the map; `lsl.l #7,d7 / lea 0(a1,d7.l),a1` shifts a 16-bit tile number as a LONG; and the per-row map skip `moveq #0,d7 / move.w d2,d7 / subi.w #$10,d7 / adda.l d7,a0` is UNSIGNED, so a stride below $10 advances the cursor by nearly 64 KB instead of stepping it back. ONE `bsr` caller, $f994.

cmt 0xfd46 198 bytes, reconstructed.
